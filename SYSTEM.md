# Как устроена система — обзор

Это не чат-сессия, а автоматизированный конвейер (как у тебя в n8n, но
рабочая логика — не визуальные ноды, а два "воркера" на базе Claude,
которые запускаются по расписанию, читают состояние проекта из
git-репозитория и сами решают, что делать дальше). Между запусками у
них **нет памяти** — единственная память проекта это сам репозиторий
(файлы CHARTER.md, PORTFOLIO.md, cases/*). Каждый запуск читает эти
файлы заново и продолжает оттуда.

## Где физически "живёт" агент

Не в этом чате. Это два **облачных cron-роутина** (RemoteTrigger /
claude.ai Routines), привязанных к репозиторию
`github.com/kostinrus36-debug/business-agent`:

### 1. `business-incubator-weekly` — воскресенье, 17:00 (UTC)
- ID: `trig_01HYMqAWvDQmqjfeF96xxqx7`
- Область: **весь портфель** — проходит по каждому не закрытому (⚪)
  кейсу и продвигает его минимум на один конкретный реальный шаг.
- Что делает за один проход:
  1. Читает CHARTER.md (правила) и PORTFOLIO.md (текущий статус)
  2. По каждому кейсу — конкретное действие, не "разговоры"
     (исследование, черновик, код, файл, конкретная подготовленная
     задача)
  3. Если начинает новое направление или крупный разворот — сначала
     письменно фиксирует план в файле кейса, потом делает
  4. Готовит всё, что упирается в физическую границу (деньги, аккаунты,
     пароли) как **готовый пакет** в PORTFOLIO.md → "Needs owner
     approval" — одним списком, не россыпью мелких вопросов
  5. **Ежемесячно (встроено в этот же проход):** смотрит историю
     PORTFOLIO.md, закрывает кейсы без прогресса 3 недели подряд,
     предлагает замену. Пересматривает, не пора ли сконцентрироваться
     на одном сильном направлении вместо распыления.
  6. Коммитит и пушит в main с понятным сообщением
  7. В конце — человекочитаемый отчёт (это то, что ты видишь как
     результат недели)

### 2. `nachtrag-app-daily-spec` — каждый день, 18:00 (UTC)
- ID: `trig_01AdwaJuWeosFyTm1wP3DVUf`
- Область: **только Кейс Б** (Nachtrag-приложение для строителей) —
  остальные кейсы не трогает
- Что делает за один проход: берёт ОДНУ конкретную тему вглубь (не
  поверхностный проход по всему) — стандарт одной специализации,
  сценарий спора с заказчиком, разбор конкурента, UX-экран, юридическая
  деталь. Проверяет всё через реальный веб-поиск, никогда не выдумывает
  DIN-стандарты/отзывы/юридические факты — либо подтверждает
  источником, либо явно помечает как непроверенное. Переписывает
  technical-foundation.md на месте (не копит "## Update от даты").

## Постоянное правило для обоих: мониторинг продаж и готовность к развороту

Не только "делать шаги вперёд" — оба воркера обязаны реально смотреть
на результат (продажи, трафик, отклик) и **не держаться за направление
из инерции**. Правило ротации в CHARTER.md — это именно это: 3 недели
без реального прогресса = кейс закрывается или переформулируется.
Ассортимент (какие конкретно товары/дизайны/позиции внутри кейса) —
тоже предмет постоянного пересмотра, не разовое решение при запуске.

## Роль владельца (тебя)

Ты не пишешь код и не гоняешь агента вручную по мелочам. Твоя роль —
раз в неделю (или когда удобно) открыть PORTFOLIO.md → "Needs owner
approval" и одобрить/отклонить пакет решений, которые агент физически
не может сделать сам (создание аккаунтов, ввод паролей, реальные
платежи). Всё остальное — стратегию, тактику, конкретные шаги — воркеры
решают сами, по правилам CHARTER.md.

## Проверить, что воркеры реально работают
`RemoteTrigger action:list` — покажет оба, их расписание и
`next_run_at`. `RemoteTrigger action:list_runs` по trigger_id — история
реальных запусков. История коммитов в git — самое надёжное
подтверждение, что что-то реально сделано (не просто "запланировано").
